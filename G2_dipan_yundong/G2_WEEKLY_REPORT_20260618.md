# G2 机器人项目周报

周期：2026-06-15 至 2026-06-18  
汇报人：Davie

## 一、本周工作概述

本周围绕 G2 机器人在工业场景中的实机运行、远程音视频链路、系统架构理解、GDK 二次开发和 VLA/世界模型方案设计持续推进。整体进展是：map20 场景七根料杆自动化流程已经完成实机闭环验证，头部摄像头与音频远程访问链路已经打通，G2 系统架构和二开文档已经形成，同时完成了头部关节远程控制验证，为后续隧道环境下远程操作、数据采集和 VLA 推理接入打下基础。

## 二、本周重点进展

### 1. map20 七根料杆自动化流程实机跑通

本周完成了 G2 在 map20 场景下七根料杆搬运流程的连续实机验证。

主要结果：

- 完成 rod 1 单根冒烟验证。
- 完成 rod 2 至 rod 7 连续运行验证。
- 针对中断恢复场景，完成 rod 4 已抓取状态下的安全恢复，避免重复执行开夹爪、重新抓取等危险动作。
- 最终任务状态达到 `MISSION_DONE`，机器人回到 `HOME_SAFE`，并确认 `holding_rod=false`。
- 运行后检查未发现 Traceback、Exception、KeyboardInterrupt 或非零返回码。
- 机器人底层状态检查正常，`motion_control_error=0`，整机错误码为 0，任务结束后底盘静止。

关键节拍数据：

- `LOCAL_PLACE` 平均约 62.268 秒。
- `LOCAL_PICK` 平均约 35.752 秒。
- `NAV_TO_PLACE` 平均约 16.989 秒。
- `NAV_TO_RECOVERY` 平均约 16.426 秒。
- `NAV_TO_HOME` 平均约 11.629 秒。

本项工作说明当前 map20 站点的核心搬运流程已经具备可重复验证基础，下一步可以围绕节拍优化、异常恢复和数据采集做工程化增强。

### 2. 机器人执行脚本工程化与架构整理

对七根料杆执行代码进行了结构化梳理，将原本偏脚本式的执行逻辑拆分为更清晰的主流程入口和 G2 primitive 能力层。

本周整理后的结构包括：

- 主入口：`rack_hybrid_docking_package/industrial_cell_7_rods_single_debug.py`
- 可复用能力层：`g2_primitives`
- 保留旧 CLI 脚本兼容能力，避免影响已有调用方式。
- 为关键流程补充注释和交接文档，便于后续继续调试、回退和交接。

这部分工作的价值是降低后续扩展成本，特别是后面要接入视觉采集、VLA 策略、异常恢复和世界模型时，不需要继续堆叠临时脚本。

### 3. 远程头部视频与音频链路打通

本周重点排查了 G2 头部摄像头、语音板和网页端实时查看能力。

已完成：

- 通过 GDK 官方头部相机能力获取头部视频流。
- 通过 AISpeech 头部语音板获取实时 PCM 音频流。
- 搭建浏览器端实时查看页面，当前可通过本地隧道访问头部视频和音频。
- 针对音频卡顿问题，调整了浏览器端播放参数，包括低码率视频模式、8 kHz mono 播放和音频缓冲策略。
- 梳理出官方 RTC 链路受 TRRO、Agora 凭证和私有网络限制，当前更适合采用自建 viewer + SSH 隧道方式。

当前状态：

- 头部视频链路已经可用。
- 头部音频链路已经可用，但在网络抖动时仍会出现卡顿。
- 当前链路适合在隧道或弱公网环境下继续优化，但需要进一步增强重连、缓冲和网络质量监控。

### 4. G2 系统架构深入梳理

本周对 G2 实机系统架构进行了深入分析，并形成了架构文档。

已确认的关键架构信息：

- 实机系统基于 Jetson AGX Thor。
- 当前 GDK 版本为 `2.6.3`。
- AORTA 版本为 `2.2.0`。
- Cosine bus 版本为 `3.5.0`。
- 启动链路为 `genie_app.service -> /home/agi/app/bin/run.sh -> FastDDS/AORTA -> launcher -> manifest scene base -> HAL/SLAM/motion-control/task_manager/GDK service`。
- 控制链路可以概括为：GDK/Pnc/Robot/Slam/Map/TF -> nav/motion/task -> HAL -> EtherCAT/CAN/power board/actuators。
- 头部板卡为 RK3588S，语音服务为 AISpeech，提供 TTS、ASR、音频播放、音量设置等接口。

本项工作沉淀为文档：`G2_LIVE_ARCHITECTURE_DEEP_DIVE_20260618.md`。

### 6. 实机头部关节远程控制验证

本周完成了 G2 头部关节远程控制验证。

执行结果：

- 按需求将机器人头部向右转动较大角度。
- 高层 GDK 头部接口出现 `Config request timeout`，说明高层配置服务或接口链路仍需继续排查。
- 通过 WBC servo 底层关节控制接口完成头部 yaw 控制。
- 实际目标角度约为 `-0.60 rad`，约等于向右转 `34.4°`。
- 运动后检查：头部 yaw 到达约 `-0.599883 rad`，pitch/roll 为 0，`neck_error=0`，`chassis_error=0`，整机错误码为 0。

本项验证说明，即使高层 GDK 头部接口存在配置超时，底层 WBC 关节控制路径仍然可用于受控验证。但后续正式使用时仍建议优先修复或确认官方高层接口。

## 三、当前问题与风险

### 1. 网络稳定性仍是主要风险

本周远程访问过程中多次出现网络不稳定现象，包括 `No route to host`、`Destination Host Unreachable`、邻居表 `FAILED/INCOMPLETE` 以及高延迟抖动。该问题会直接影响：

- 浏览器端视频打开速度。
- 音频连续性。
- SSH 隧道稳定性。
- 实机远程控制响应。

建议下周优先增加网络质量检测、自动重连和低带宽模式切换。

### 2. 官方 RTC 链路暂时不适合作为主路径

官方 RTC 路径目前受 TRRO、Agora 凭证和私有网络环境限制，短期内不适合依赖其作为稳定远程视频主链路。当前自建 viewer + SSH 隧道是更可控的路线。

### 3. 高层 GDK 头部运动接口存在超时

高层 `move_head_joint` / `joint_control_request` 出现配置请求超时，但底层 WBC servo 可用。该问题需要继续定位是配置服务、接口依赖、GDK 初始化还是运行场景权限问题。

### 4. VLA 实机闭环还需要分阶段验证

当前已经明确 VLA 推理接口和动作格式，但还没有直接进入实机闭环动作执行。后续应按顺序推进：

- 策略服务端启动验证。
- GDK 客户端 dry-run。
- 动作范围和安全门禁检查。
- 单步小动作实机验证。
- 最后再接入完整任务闭环。
